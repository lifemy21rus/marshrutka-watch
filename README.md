# marshrutka-watch

Следит за городской маршруткой и присылает push-уведомление на телефон
**заранее до того, как маршрутка подъедет** — чтобы wife успела выйти из дома.

* Источник данных: **Яндекс.Карты** (реальный прогноз прибытия по остановке).
* Канал доставки: **ntfy** — бесплатное приложение для iOS и Android, push работает
  без интернета-звонилки и без своего сервера.
* Умеет определять, **с какой стороны** подъедет маршрутка (это важно, если остановку
  обслуживают два прохода кольцевого маршрута).
* Ноль зависимостей: только стандартная библиотека Python 3.8+.

---

## 1. Как это работает

Программа раз в минуту (по умолчанию) делает три запроса к Яндекс.Картам:

| Страница | Что берём |
|---|---|
| `/maps/45/cheboksary/stops/stop__10094747/` | прогноз прибытия по каждому маршруту: время, интервал, id машин |
| `/maps/45/cheboksary/routes/minibus_5/…` | геометрию маршрута: порядок остановок и трек (43,8 км, 89 остановок) |
| `/maps/45/cheboksary/transport/minibuses/` | живые координаты машин и их траектории |

Все три страницы отдают данные прямо в HTML (Яндекс рендерит их на сервере),
поэтому парсинг лёгкий и не ломается от смены вёрстки карточек.

Опрос и запись снимка выполняются **каждый цикл независимо от окна слежения** —
веб-панель всегда показывает свежие данные. Уведомления при этом шлём **только
внутри окна** (`window_from`–`window_to` с учётом `weekdays_only` и `window_by_weekday`).
При ошибке источника используется последний удачный снимок (запасной источник).

### Как определяется сторона

Маршрутка №5 в Чебоксарах — **кольцевой**: «Мicroрайон Солнечный-2 → ЧПО имени Чапаева → обратно»,
и остановку «Медицинский центр» он проходит **дважды за круг — с двух разных сторон**:

* проход №1 (11,1 км маршрута) — подъезд **со стороны «Пригородного автовокзала»**;
* проход №2 (33,0 км маршрута) — подъезд **со стороны «Лакреевского леса»**.

Яндекс в прогнозе **сливает оба прохода в один** и отдаёт просто «Маршрутка 5 — 5 мин»,
из-за чего непонятно, откуда подъедет. Программа разделяет их:

1. **Ветка по пройденному пути** — у кольцевого маршрута участок трека рядом с
   остановкой физически совпадает в обоих проходах, поэтому по «ближайшей точке»
   ветку не определить. Мы сравниваем весь путь машины (траектория Яндекса плюс
   накопленная история между опросами) с цепочками остановок каждой ветки:
   одна идёт от Пригородного автовокзала, другая — от Лакреевского леса.
2. **Совпадение по времени** — если машина едет без GPS, подбираем по расчётному времени.
3. **Логика исключения** — если прибытие не объясняет ни одна видимая машина,
   а все видимые машины едут к другому проходу, значит прибытие — с противоположной стороны.

Направление подписи: подъезд **от Пригородного автовокзала** — «в сторону ЮЗР»,
подъезд **от Лакреевского леса** — «в сторону НЮР».

Выбор прохода (`_pick_branch`) для кольцевого маршрута: сначала ориентир по
проходимому пути машины (`pass_score`), при неразличимых ветках — по минимальному
расстоянию до остановки. Live-ETA собираются из живых машин (`_live_arrivals`) и
подставляются в расписанные прибытия как `live: true`; если живых данных нет —
применяется последний удачный прогноз.

## 2. Установка

### Вариант A. VPS (рекомендуется)

Работает круглосуточно, даже когда дома выключен свет. Нужен любой VPS с Ubuntu/Debian.

```bash
sudo apt update && sudo apt install -y python3
sudo useradd -r -m -d /opt/marshrutka-watch marshrutka
sudo cp marshrutka_watch.py webconfig.py marshrutka-watch.service marshrutka-web.service /opt/marshrutka-watch/
sudo cp config.example.json /opt/marshrutka-watch/config.json
```

Отредактируйте `config.json` — главное это `ntfy_topic` (придумайте случайную строку,
чтобы никто чужой не подписался на ваши уведомления) и `routes`.

Запуск вручную для проверки:

```bash
cd /opt/marshrutka-watch
python3 marshrutka_watch.py --once          # разовый опрос, печатает прогноз
python3 marshrutka_watch.py --selftest      # подробный дамп всех данных
python3 marshrutka_watch.py --test-notify   # проверка канала ntfy
```

### Вариант B. systemd-сервис (автозапуск + перезапуск)

```bash
sudo cp marshrutka-watch.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now marshrutka-watch
sudo journalctl -u marshrutka-watch -f       # живые логи
```

### Вариант C. Docker

```bash
docker compose up -d
docker compose logs -f
```

### Вариант D. Свой компьютер (Windows)

```powershell
python marshrutka_watch.py --config config.json
```

### Вариант E. Веб-панель настроек (необязательно)

Панель позволяет менять окно слежения, пороги уведомлений и частоту повторов с телефона.
Слушает только `127.0.0.1:8080`, наружу — через nginx с HTTPS и паролем.

```bash
sudo cp marshrutka-web.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now marshrutka-web

# задать логин/пароль (пароль сгенерируется, если не указать --password)
runuser -u marshrutka -- python3 /opt/marshrutka-watch/webconfig.py --set-password
```

Пример блока для nginx (в `server { listen 443 ssl; ... }`):

```nginx
location = /marshrutka { return 301 /marshrutka/; }
location /marshrutka/ {
    proxy_pass http://127.0.0.1:8080/;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto https;
    proxy_read_timeout 70s;
}
```

Вход на панель — через обычную форму (логин и пароль), сессия хранится в cookie
`mw_session` на 7 дней; ссылка «выйти» — внизу страницы. Кнопка «Сохранить»
меняет окно слежения, пороги и время до остановки; изменения применяются в течение
минуты без перезапуска (в логе появляется «настройки обновлены»).

В блоках «Сейчас на остановке» и «Наблюдаемость и антиспам» видно текущий прогноз, статус трекера (в окне слежения или нет, время последнего опроса/успеха/ошибки), последнее уведомление, причину пропуска (антиспам) и недавние события.

В блоке «Сейчас на остановке» подпись у каждой строки поясняет источник данных:
**«прогноз»** — машину видно в эфире (есть GPS, положение подтверждено),
**«прогноз, без GPS»** — Яндекс считает время по расписанию, самой машины в слое
на карте пока может не быть (слой отдаёт только машины центрального района).
В этом случае время arrival стоит доверять, но маршрутка может появиться на карте
позже.

Кнопка «Проверить уведомление» отправляет тестовый пуш в ntfy тем же кодом, что и
трекер: удобно убедиться, что канал и подписка телефона работают, не дожидаясь
маршрутки. Та же проверка из консоли:

```bash
runuser -u marshrutka -- python3 /opt/marshrutka-watch/marshrutka_watch.py \
    --config /opt/marshrutka-watch/config.json --test-notify --once
```

Пароль меняется командой выше (`--set-password`). Сессии сохраняются в файле
`web_sessions.json`, поэтому перезапуск `marshrutka-web` больше не выкидывает
из аккаунта — войти заново придётся только по истечении 7 дней.

Панель открывается мгновенно: страница отдаётся из кэша, а прогноз подтягивается
фоном и обновляется в браузере раз в 20 секунд (кнопка «Обновить» — принудительно,
теперь ждёт свежие данные от фона и отдаёт их, а не мгновенно старый кэш).
Трекер складывает последний прогноз в `last_arrivals.json`, и панель читает его
оттуда, не делая второй запрос к Яндексу. Снимок обновляется и вне окна слежения —
поэтому прогноз в панели виден всегда, даже когда уведомления выключены.

Если в блоке «Сейчас на остановке» пусто — там показывается конкретная причина:
ошибка/недоступность Яндекса, «вне окна слежения», ошибка последнего опроса или
«машины в эфире пока нет». Это же причина пишется в журнал трекера.

### Окна по дням недели

Помимо общего окна (`window_from`–`window_to`) можно задать окно per день недели
через JSON-поле `window_by_weekday` в `config.json` или через поле на панели
(та же секция «Когда следить»):

```json
{
  "window_from": "08:30",
  "window_to": "09:10",
  "window_by_weekday": {
    "1": ["08:30", "09:10"],
    "2": ["08:30", "09:10"],
    "3": ["08:30", "09:10"],
    "4": ["08:30", "09:10"],
    "5": ["08:30", "09:10"]
  }
}
```

Ключи — номера дней недели (`0` = пн … `6` = вс) или названия (`mon`, `tue`, …).
Значение — массив `[с, до]` в формате `ЧЧ:ММ`. Дни без своего окна используют
общий `window_from`/`window_to`. Например, чтобы слежение было только в
утренние часы в будни, а в выходные не следить вообще — оставьте `weekdays_only: true`
или задайте окна и для `sat`/`sun` как `["00:00", "23:59"]`.

### Запасной источник данных

Если Яндекс внезапно перестаёт отвечать, трекер не уходит в «пустоту»: он показывает
последний удачный прогноз (та же остановка, те же маршруты) и помечает ошибку в
статусе/диагностике — в панели это видно как «Ошибка последнего опроса». С этим
снимком работает и веб-панель, и механизм уведомлений (для записей без GPS источник
остаётся расписание, время — ориентировочное).

### Вариант F. Деплой с компьютера

Вместо ручной заливки файлов по SSH используется `deploy.py` + файл настроек
`deploy.env` (шаблон — `deploy.env.example`).

```bash
pip install paramiko                 # единственная зависимость
cp deploy.env.example deploy.env     # поправить HOST/пути под свой сервер
export VPS_PASS=секрет                # пароль в файле настроек НЕ хранится

python deploy.py                     # залить код и перезапустить сервисы
python deploy.py --check             # только проверить состояние сервера
python deploy.py --dry-run           # показать, что будет залито
python deploy.py --config            # заодно залить config.json
python deploy.py --units             # заодно залить systemd-юниты
python deploy.py --no-restart        # не перезапускать сервисы
```

В `deploy.env` задаются: сервер и пользователь SSH, каталог проекта на сервере,
список файлов, имена сервисов, публичный адрес панели, каталог для снимка
прогноза. Скрипт после заливки сам проверяет, что сервисы активны и панель
отвечает, и пишет предупреждения, если что-то не так.

## 3. Настройка телефона

1. Установите **ntfy** из App Store (iOS) или Google Play (Android).
2. В приложении нажмите **«+» → «Add subscription» → «Topic»** и впишите
   тот же топик, что в `config.json`.
3. Включите уведомления для этого топика.
4. Проверьте: `python3 marshrutka_watch.py --test-notify` — должно прийти push.

> Топик на публичном ntfy.sh виден всем, кто знает его имя. Поэтому берите
> случайную строку (например `mdw-3f9a1c7b-e42d`) либо заведите бесплатный
> аккаунт на ntfy.sh и укажите `ntfy_token` — тогда топик будет приватным.

### Секреты и доступ

- Чувствительные параметры ntfy можно передавать через переменные окружения (приоритет над `config.json`): `MARSHRUTKA_NTFY_TOKEN`/`NTFY_TOKEN`, `MARSHRUTKA_NTFY_TOPIC`/`NTFY_TOPIC`, `MARSHRUTKA_NTFY_SERVER`/`NTFY_SERVER`.
- Веб-панель не показывает и не редактирует токен/топик ntfy. Ограничьте доступ к ней (слушает `127.0.0.1`, публикуйте только через HTTPS + пароль) и защитите права на файлы конфигурации/авторизации (`config.json`, `web_auth.json`, `web_sessions.json`).

## 4. Ключевые параметры

| Параметр | По умолчанию | Что значит |
|---|---|---|
| `routes` | `["5"]` | список маршрутов (номера) |
| `stop_id` | `stop__10094747` | id остановки в Яндекс.Картах |
| `region_id` / `city` | `45` / `cheboksary` | город |
| `interval` | `60` | как часто опрашивать, секунд |
| `window_from` / `window_to` | `05:30` / `10:00` | рабочее окно (время города, не VPS) |
| `window_by_weekday` | `{}` | окна per день недели, например `{"1": ["08:30", "09:10"], "2": ["08:30", "09:10"]}` (ключ — номер дня `0`=пн…`6`=вс или название `mon`…`sun`, значение — `[с, до]` в `ЧЧ:ММ`); без дня берётся общее окно |
| `notify_at` | `[15,10,5,2]` | за сколько минут до прибытия присылать уведомления (можно указать любые пороги, например `[20,15,10,5,2]`) |
| `notify_repeat_minutes` | `1` | как часто повторять уведомления об одной и той же маршрутке в режиме повтора: `1` — при каждом опросе (по умолчанию, примерно каждую минуту), `2` — не чаще раза в 2 минуты и т.д. |
| `notify_mode` | `"repeat"` | режим антиспама: `"repeat"` — повторять уведомления с интервалом `notify_repeat_minutes`, пока маршрутка в зоне порогов; `"once"` — отправить один раз на каждый порог (15/10/5/…) для одной поездки |
| `walk_minutes` | `0` | если маршрутка будет раньше этого числа минут, добавить «⏰ Пора выходить!» (`0` — выключено) |
| `route_settings` | `{}` | переопределения настроек по маршрутам (разные пороги/режим/повтор/`walk_minutes`), например `{"5":{"notify_at":[20,15,10,5],"notify_mode":"once"}}` |
| `side_min_back_m` | `700` | как далеко назад по маршруту искать ориентир для названия стороны |
| `weekdays_only` | `false` | если `true` — по субботам и воскресеньям трекер молчит |
| `snapshot_path` | — | куда писать снимок прогноза для панели (нужно, если каталог конфига только для чтения) |
| `default_speed_mps` | `8.0` | средняя скорость, если у машины нет GPS |

Время окна считается по **городскому** времени (Чебоксары = UTC+3), а не по времени VPS.

### Как узнать `stop_id` и `city`

Откройте остановку в Яндекс.Картах и скопируйте адрес:
`https://yandex.ru/maps/45/cheboksary/stops/stop__10094747/`
→ `region_id=45`, `city=cheboksary`, `stop_id=stop__10094747`.

### Как узнать `region_id` и `city` для другого города

Тот же адрес остановки, только с нужным городом. Либо найти остановку в
[Яндекс.Картах](https://yandex.ru/maps) и открыть «Ссылка» на остановке.

## 5. Пример уведомления

> **Маршрутка 5 — через 5 мин**
> Прибудет на остановку «Медицинский центр» в 16:05 (через 5 мин).
> Подъедет со стороны «Ярмарка».
> до «Микрорайон Солнечный-2».

Если в конфиге задано `"walk_minutes": 5`, то при прибытии через 5 минут и
меньше заголовок меняется на «Маршрутка 5 — 5 мин, пора выходить», а в тексте
появляется строка `⏰ Пора выходить!` — удобно, когда до остановки идти
несколько минут.

## 6. Если что-то пошло не так

**«нет JSON-стейта на ...»** — Яндекс поменял разметку. Скопируйте HTML страницы
и проверьте, что внутри есть `<script type="application/json" class="state-view">`.

**Пустой прогноз по маршруту** — маршрутка не ходит в это время (ночь/перерыв)
или у маршрутки нет GPS. Посмотрите `--selftest`: там видно интервалы и расписание.

**Уведомления не приходят** — проверьте `--test-notify`, затем подписку в приложении ntfy
и совпадение топика. На приватном ntfy нужен `ntfy_token`.

**`Network is unreachable` при отправке в ntfy** — у некоторых VPS есть IPv6-адрес,
который не работает. Скрипт принудительно использует IPv4 и делает 3 попытки,
так что эта ошибка не должна повторяться. Если повторяется — проверьте
`curl -4 https://ntfy.sh` и `curl -6 https://ntfy.sh` на сервере.

**Яндекс заблокировал запросы** — программа сама переживает ошибки, увеличивает паузу
и пишет в лог. Не опрашивайте чаще раза в 30 секунд.

**Направление не совпадает с картой** — проверить выбор прохода в `_pick_branch()` (ориентир по пути + tie-break) и ветку в `approach()`; у кольцевого
маршрута остановку проходит дважды, поэтому ошибка может быть в выборе прохода.

## 7. Формат данных

Всё берётся из серверного рендера Яндекс.Карт (публичного API у Яндекса нет).
Если разметка изменится, чинить проще всего в трёх местах файла:

* `fetch_state()` — достаёт JSON-стейт страницы;
* `RouteGeometry.from_route_state()` — строит трек и список остановок;
* `Tracker.stop_arrivals()` / `Tracker.vehicles()` — разбирают прогноз и машины.
